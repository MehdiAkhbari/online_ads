HYPERPARAMETER CHOICES FOR THE CAUSAL FOREST (adsim.estimate)
================================================================

This documents where min_samples_split, min_samples_leaf, max_samples,
max_depth, and n_estimators (CausalForestDML, fit in
adsim.estimate.fit_one_rank) come from, and how they were chosen.

As of the N-adaptive rewrite in adsim/hyperparams.py, only TWO
causal-forest parameters are cross-validated per pair (min_samples_leaf,
min_var_fraction_leaf, via cf.tune()); everything else is derived from
that pair's own (n_base, n_focal) by a formula, not discovered by
comparing candidates. The reasoning below explains why: the deciding
statistical constraint is known in advance from the click rate and each
pair's sample composition, so cross-validation doesn't have anything to
"discover" that the formula doesn't already determine.

THE CORE CONSTRAINT: CLICKS IN THE MINORITY ARM PER LEAF
----------------------------------------------------------
is_clicked averages about 0.1% across the data. A tree leaf of size N
has an expected click count of roughly click_rate * N, and (treating
clicks as a rare Bernoulli event) the leaf's own click-rate estimate has
relative standard error of about 1 / sqrt(click_rate * N):

    leaf size    expected clicks    relative SE of leaf's rate
    ---------    ---------------    --------------------------
        2,000            2                    ~71%
        5,000            5                    ~45%
       10,000           10                    ~32%
       20,000           20                    ~22%
       50,000           50                    ~14%
      100,000          100                    ~10%

"A few clicks" (5-20) still means 20-45% relative noise per leaf --
enough to detect large heterogeneity, not fine distinctions. ~10%
precision needs leaves near 100K, which is at or beyond the *entire*
combined sample size for several of the rarer advertiser ranks (every
per-rank fit combines the base ad, ~100K rows, with that rank's own
rows, which range from ~150 to ~2.6M). That's a real ceiling set by the
data, not something any hyperparameter choice can lift.

The constraint that actually binds isn't leaf size in rows -- it's
clicks in the MINORITY arm per leaf. For a pair, the expected minority-
arm click count in a leaf of size L is roughly
`L * click_rate * min(n_base, n_focal) / N`. Because the base ad has a
fixed ~100K rows while the focal rank's rows range up to ~2.6M, uniform
subsampling of a large pair spends most of each tree's budget on the
already-plentiful focal arm and leaves very few base-arm clicks per
tree -- that, not tree depth, is what limited the old fixed-number rule.

CAPPING THE FOCAL ARM AT ~3x THE BASE ARM
--------------------------------------------
Past a 3:1 ratio, the majority arm's contribution to Var(tau_hat) (the
1/n_majority term) is already negligible, but it still consumes most of
a tree's per-tree sample budget. adsim.hyperparams.cf_hyperparams
subsamples the focal rank's rows down to
`min(n_focal, focal_cap_ratio * n_base)` (default ratio 3.0) before
fitting. This raises the minority arm's share of each tree's budget at
~identical tree cost, and it bounds every pair's total N at a
manageable size regardless of how popular the ad is -- solving most of
the old runtime blowup on the largest ranks as a side effect.

max_samples = min(max_samples_cap, N // 2)  (N = capped pair total)
-----------------------------------------------------------------------
The `// 2` is not optional: econml raises `ValueError` if an integer
`max_samples` exceeds `n_samples // 2` under `inference="blb"` (used by
cf.fit(...) below). `max_samples_cap` defaults to 100,000
(--max-samples-cap). Because this is now computed from each pair's own
(capped) N instead of being one fixed number, small ranks and large
ranks both get an appropriately-sized per-tree budget instead of the
smallest ranks being squeezed hardest (which is what a single fixed
absolute value did).

min_samples_leaf: {H // 4, H // 2}, where H = max_samples // 2
--------------------------------------------------------------------
This is the parameter that actually floors leaf size, and it's the
first of the two parameters cross-validated via cf.tune(). It's
expressed as a function of H (half of max_samples) rather than a fixed
number because honest=True splits each tree's own subsample into a
splitting half and an estimation half, and econml enforces the leaf
floor on BOTH halves and BOTH children of a split -- so `H // k` means
roughly "allow up to k leaves per honest half," a real, interpretable
complexity difference (e.g. "4 leaves vs 2 leaves") for cf.tune()'s
R-score to compare, rather than three candidates that all produce
structurally identical trees.

min_var_fraction_leaf: {0.01, 0.1}
--------------------------------------
The second (and only other) cross-validated causal-forest parameter.
Forces Var(T | leaf) >= c * Var(T), guarding against leaves with
near-degenerate treatment variation producing exploding CATE estimates
(this directly answers a referee concern about out-of-range
predictions). Previously unset (econml default: None / disabled).

min_samples_split = 2 * min(leaf grid)
-------------------------------------------
Deliberately non-binding: a node can't be split unless BOTH children can
meet the leaf floor, so min_samples_split must be at least 2x the
smallest leaf candidate for a split to even be mechanically possible.
Not cross-validated -- letting it vary independently of the leaf floor
only makes the grid harder to interpret without adding information.

max_depth: 3 (fixed, not cross-validated)
------------------------------------------------
With min_samples_split/min_samples_leaf this large relative to
max_samples, the leaf/split floor is the practical stopping rule long
before depth becomes relevant -- trees are expected to manage at most a
couple of splits before hitting the floor regardless of whether
max_depth is 3, 10, or 30. A larger max_depth than needed just spends
tune() time producing structurally identical trees.

n_estimators: 500 (production default; --n-estimators for quick tests)
------------------------------------------------------------------------
More trees reduce the variance of the forest's aggregated CATE estimate
and matter directly for BLB-based inference (cf.fit(...,
inference="blb", ...)) approximating its asymptotic distribution well.
500 must remain divisible by econml's subforest_size (default 4) for
BLB subsampling; 500 / 4 = 125 exactly.

honest=True, min_balancedness_tol=0.45, criterion="het"
------------------------------------------------------------
honest=True and min_balancedness_tol=0.45 are econml's own defaults for
this econml version -- fit_one_rank now passes them explicitly so the
choice is documented rather than implicit. criterion="het" (the
heterogeneity-maximizing split criterion) is unchanged from before.

THE NUISANCE MODELS: m(X) = E[Y|X] AND e(X) = P(T=1|X)
=========================================================
Both are grid-searched (adsim.hyperparams.m_model_best_estimator /
e_model_best_estimator) over a single parameter, min_samples_leaf, with
everything else fixed:

  - max_features="sqrt" is fixed (not searched) for both. sklearn's
    RandomForestRegressor/RandomForestClassifier default to
    max_features=1.0 / "sqrt" varies by version, but leaving it
    unspecified previously meant searching (effectively) all 37
    covariates at every split on up to ~2.7M rows -- the single biggest
    avoidable cost in nuisance fitting. sqrt(37) ~= 6 cuts split-search
    work roughly 6x; for nuisance prediction quality this costs nothing
    measurable, since m(X)/e(X) only need to be "good enough" for
    orthogonalization, not the final object of interest.
  - n_estimators=100, cv=3 for both (down from the previous shared
    9-combo x cv=5 grid over max_depth/min_samples_split).
  - m(X) is scored by neg_mean_squared_error; leaf-size candidates are
    min(10/click_rate, N/40) and min(100/click_rate, N/10) -- targeting
    ~10 and ~100 expected clicks per leaf, capped as an absolute
    fraction of N so the grid stays sane even for a near-zero click
    rate. m(X)'s leaves end up large, and that's correct: a pair sample
    holds only a few hundred clicks total, so m(X) genuinely cannot
    resolve more than that -- and under orthogonality, m(X)'s error
    enters tau_hat only multiplied by e(X)'s error, so over-smoothing
    m(X) is the cheap direction to err in.
  - e(X) is scored by neg_log_loss (previously F1) -- DML needs a
    calibrated probability, not a thresholded decision, and with arm
    shares as lopsided as 150-vs-100,000 rows, F1 will happily select a
    model that predicts the majority class everywhere.
    adsim.propensity_model.PropensityModel.score() was fixed the same
    way, since econml also calls that method internally during
    cf.tune() regardless of which scorer GridSearchCV was given
    explicitly. e(X)'s leaf-size candidates are
    min(10/rare_rate, N/100) and min(50/rare_rate, N/20), where
    rare_rate = min(n_base, n_focal_used)/N -- e(X) needs the RARE arm's
    representation bounded away from 0/1 (the binding count here is
    treated units, not clicks), so its target uses the rare-arm rate,
    not the click rate.

WHY THESE CAUSAL-FOREST PARAMETERS AREN'T ALL CROSS-VALIDATED
--------------------------------------------------------------------
The nuisance-model grids (m/e) make sense to cross-validate: which
min_samples_leaf best predicts Y or T is an ordinary prediction
question CV can answer. But for the causal forest's own max_samples /
min_samples_split / max_depth, the deciding constraint (enough clicks in
the minority arm per leaf, given this pair's own composition) is known
in advance from click_rate and (n_base, n_focal) -- CV comparison across
candidates has no way to "discover" a statistical requirement like that
better than just computing it, and letting them vary independently
re-introduces exactly the kind of hard-to-interpret grid (three
structurally identical trees) the old max_depth grid produced.

A REAL BUG THIS RULE ALSO FIXES: cf.tune() overriding the final
model's hyperparameters
-------------------------------------------------------------------
econml's CausalForestDML.tune() writes EVERY key in the `params` dict
passed to it back onto the estimator object via `setattr(self, key,
value)` -- not a copy. Anything not in that dict (n_estimators,
max_depth, min_samples_split under the current rule) is left exactly as
the constructor set it; only min_samples_leaf and min_var_fraction_leaf
are meant to be touched by tune(), and they are the only two in the
dict passed to cf.tune() in fit_one_rank.

CLI OVERRIDES
--------------
adsim.estimate accepts --n-estimators, --max-depth, --focal-cap-ratio,
--max-samples-cap (defaults: 500, 3, 3.0, 100_000). The old
--min-samples-split / --min-samples-leaf / --max-samples flags are gone
-- those are now derived per pair, not settable as flat absolute
overrides.

DEFERRED / NOT IMPLEMENTED (discussed, intentionally left for later)
========================================================================
The design discussion behind this rule also worked out three further
pieces of machinery that are NOT implemented here:

  1. A click-based feasibility ladder per pair: minority-arm clicks == 0
     or minority rows < 30 -> degenerate (single-leaf forest, flagged
     homogeneous effect, still returned through the same interface so no
     rank is ever silently dropped from ranks_list); minority clicks <
     25 -> force a single-leaf ATE-only forest; otherwise -> normal
     CATE fit. Right now every pair goes through the same
     cf_hyperparams path regardless of how few realized clicks it ends
     up with -- the zero-rate guards in m_model_leaf_grid /
     e_model_leaf_grid only prevent a crash, they don't implement this
     ladder's statistical treatment of a near-empty pair.
  2. A `freeze=` robustness mode: re-running the split/duopoly scenarios
     with the monopoly scenario's own NUMERIC hyperparameters (clipped
     only where mechanically illegal) instead of each scenario computing
     its own from its own smaller N, to check whether a measured merger
     gain survives once tree geometry no longer differs by construction
     between scenarios.
  3. Tuning by size bucket (one representative large/medium/small pair,
     apply the winning nuisance-model choice within each bucket) instead
     of per pair -- the current code re-tunes m(X)/e(X) independently
     for every single rank, same as before this rewrite.
