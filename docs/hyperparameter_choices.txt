HYPERPARAMETER CHOICES FOR THE CAUSAL FORESTS (adsim.estimate)
================================================================

This file explains how every setting of the per-rank CausalForestDML
(adsim.estimate.fit_one_rank) and its two nuisance models is chosen. The
rule is implemented in adsim/hyperparams.py; each fitted forest stores
the values it used as `cf.adsim_plan_`, and
`python -m adsim.estimate --scenario ... --dry-run` prints them for every
rank without fitting anything.

THE RULE IN ONE PARAGRAPH
--------------------------
For each (base ad, rank r) pair: (1) subsample the larger arm so that
neither arm has more than 3x the rows of the other; (2) give each tree
max_samples = min(200,000, N // 2) rows, where N is the pair's size after
step 1; (3) set min_samples_leaf to the leaf size at which a leaf is
expected to hold 5 clicks from EACH arm, and min_samples_split to twice
that. Everything else is fixed: min_var_fraction_leaf = 0.1, 500 trees,
honest trees, criterion "het", no depth cap, no cf.tune().

    arm cap          n_kept(arm) = min(n(arm), 3 * n(smaller arm))
    rows per tree    max_samples = min(200_000, N // 2)
    leaf floor       min_samples_leaf  = ceil(5 * N / c_min)
                     min_samples_split = 2 * min_samples_leaf
    where c_min = expected clicks of the arm with fewer clicks
                = min over arms of n_kept(arm) * observed click rate(arm)

There are no thresholds or branches, so every setting moves smoothly
with the number of observations. (The only special case is an arm with
zero clicks, where the leaf floor is set to N, the limit of the formula.)

THE CONSTRAINT THAT DRIVES EVERYTHING: CLICKS IN THE WEAKER ARM
------------------------------------------------------------------
is_clicked averages about 0.1%. A CATE is a difference in click rates
between the two arms, so its precision in a leaf is limited by the arm
with FEWER clicks in that leaf, not by the leaf's row count. Every pair
contains the base ad, which has about 100,000 rows in the monopoly data
and therefore only about 90 clicks; for most pairs the base ad is the
weaker arm.

For one arm, a leaf holding k expected clicks estimates that arm's click
rate with a relative standard error of about 1/sqrt(k):

    expected clicks per arm    relative SE of that arm's rate
    -----------------------    ------------------------------
              1                          100%
              3                           58%
              5                           45%
             10                           32%
             20                           22%

The floor is set at 5 clicks per arm. With 1-3 clicks, each arm's rate
in a leaf is uncertain by 60-100% of its value, so the split that looks
best is essentially chosen at random. At 5 the uncertainty is about 45%,
enough to pick up large differences between user groups (the pairwise
CATEs vary by tens of percent of the base CTR). Averaging over 500 honest trees, each drawn from a different
subsample, reduces the noise of the final CATE well below that of any
single leaf. The floor exists so that the tree STRUCTURE, which decides
which users are pooled together, is not itself driven by noise.

WHAT THE LEAF FLOOR IMPLIES: LEAVES PER TREE = c_min / 20
------------------------------------------------------------
econml enforces min_samples_leaf on BOTH halves of an honest tree (the
splitting half and the estimation half; see econml/tree/_splitter.pyx),
and each half has max_samples / 2 rows. Below the per-tree cap
(max_samples = N / 2), a tree can therefore hold at most

    (N / 4) / (5 N / c_min) = c_min / 20   leaves per honest half.

So a pair gets heterogeneous (split) trees only if its weaker arm has at
least 40 expected clicks, whatever its size; otherwise every tree is a
single leaf and the forest returns a DML estimate of the average effect.
This is the intended protection against pure noise: an advertiser with
too few clicks to say anything about heterogeneity gets a constant effect,
not a random one. Worked examples (base-ad CTR 0.09%, focal CTR 0.10%):

    pair                               kept rows (base/focal)  c_min  max_samples  leaf    leaves/half
    ---------------------------------  ----------------------  -----  -----------  ------  -----------
    Monopoly, largest advertiser       100,000 / 300,000        90    200,000      22,223  4.5
    Monopoly, balanced pair            100,000 / 100,000        90    100,000      11,112  4.5
    Monopoly, 30K-row advertiser        90,000 /  30,000        30     60,000      20,000  1.5 (average effect)
    Monopoly, 150-row advertiser           450 /     150         0.2      300         600  0.3 (average effect)
    Split platform, large advertiser    50,000 / 150,000        45    100,000      22,223  2.25
    20% subsample, large advertiser     20,000 /  60,000        18     40,000      22,223  0.9 (average effect)

Consequence for the paper: the rule is the same absolute rule in every
scenario, so a smaller platform (split, Root-N, subsample) learns fewer
or no splits because it has fewer clicks, not because it was configured
differently. That is a genuine scale effect of having less data, and it
should be reported. Before the full run, count the ranks with
`max_leaves_per_tree < 2` in each scenario from --dry-run, and report
those counts (the forests themselves carry the same number in
`cf.adsim_plan_`). Lower --min-clicks-per-arm as a robustness check. At 3,
the threshold falls to 24 clicks in the weaker arm.

ARM BALANCE: NEITHER ARM MORE THAN 3x THE OTHER (--arm-ratio-cap)
-----------------------------------------------------------------------
Focal ranks range from about 150 to 2.6M rows, against about 100,000
base-ad rows. Without a cap, a tree drawn from the largest pairs is ~96%
focal rows. Its base-ad share of a 20,000-row leaf holds under one
expected click, so its splits are driven by the focal arm's noise. The
nuisance grid search also runs on 2.7M rows. The cap:

  - keeps each arm at >= 25% of every pair, so the per-tree budget
    always contains both arms in useful proportions;
  - bounds every pair at 4x its smaller arm (at most ~400,000 rows in the
    monopoly), which is what makes the runtime predictable;
  - costs a bounded amount of precision. Var(ATE) is about
    p/n_small + p/n_large; keeping 3x the smaller arm makes the second
    term at most 1/3 of the first. That is at most 33% more variance
    (about 15% wider intervals) than using every row of the larger arm,
    and only for pairs where the cap binds.

The cap is applied symmetrically, so for tiny advertisers the base ad is
subsampled too. Those pairs get an average effect anyway (see above).
The subsampling is random within each arm, which leaves the conditional
outcome distribution within each arm, and hence tau(x), unchanged. It is
seeded by --random-state, and base_ad_helpers rebuilds exactly the same
rank-1 pair.

ROWS PER TREE: max_samples = min(200,000, N // 2) (--max-samples-cap)
---------------------------------------------------------------------------
N // 2 is the largest integer econml accepts under inference="blb"
("max_samples must be in [1, n_samples // 2]"), so this can never raise.
(The previous "50000 if N > 50000 else N // 2" guard raised for every pair
of 50,000-100,000 rows: in cf.tune(), which fits on 70% of the rows, for
pairs under ~71,500, and in fit() above that.) N // 2 is also grf's
default subsample fraction.

The 200,000 cap bounds forest-building time. Measured on synthetic data
the size of the largest capped pair (400,000 rows, 8 vCPU, 100 trees):
the nuisance grid search took 179 s and the forest fit (with DML cross-
fitting) 60 s. The forest is not the bottleneck, and the full fit is a few
minutes per large pair. At a 100,000 cap the largest pairs could hold only
~1.9 leaves per honest half, i.e. no splits for the most-served
advertisers. At 200,000 they reach 4.5, the same as balanced pairs.

min_var_fraction_leaf = 0.1 (--min-var-fraction-leaf)
------------------------------------------------------
The arm cap fixes the arms' overall shares, but a leaf can still end up
with almost no rows of one arm (e.g. where the propensity varies with
X). There the local contrast is not identified and the CATE can explode.
This is referee R1.4's concern about out-of-range predictions. econml's
min_var_fraction_leaf rejects any split whose child keeps less than 10%
of the pair's treatment-residual variance.

n_estimators = 500; honest=True; criterion="het"; max_depth=None
-----------------------------------------------------------------------
500 trees keep the BLB confidence intervals stable and must be divisible
by econml's subforest size (4); the CLI rejects other values. Honest
trees are required for valid inference. With the leaf floor controlling
complexity, a depth cap would never bind, so none is set.

WHY THERE IS NO cf.tune()
--------------------------
tune() compares candidates by R-score using 100-tree forests on a 70/30
split. The previous grid had a single candidate
({'min_samples_split': [20000]}), so tune() changed nothing and roughly
doubled the cost per rank (it fits a scorer's nuisance models plus a full
DML fit). At a 0.1% click rate the R-score of small forests is too noisy
to rank genuinely different candidates reliably, and the settings that
matter follow from the click constraint above. Note that tune() writes
every key of its grid back onto the estimator (setattr), so anything put
in a grid silently overrides the constructor. That is why adsim.estimate_joint's
cf_param_grid must never contain n_estimators or max_depth.

THE NUISANCE MODELS: m(X) = E[Y|X] AND e(X) = P(T=1|X)
=========================================================
Both are random forests (100 trees, max_features="sqrt"), grid-searched
only over min_samples_leaf with 3-fold cross-validation stratified on
the target. The winning configuration is passed to CausalForestDML
unfitted, with n_jobs set, so econml's own cross-fitting also runs in
parallel. (Previously the final nuisance models were built without
n_jobs and ran on one core.)

  - m(X): scored by mean squared error (the Brier score for a binary Y).
    Leaf candidates target ~10 and ~100 expected clicks per leaf,
    min(10 / click_rate, N/40) and min(100 / click_rate, N/10). Over-
    smoothing m is the cheap direction to err in: under orthogonality its
    error enters tau_hat only multiplied by e's error.
  - e(X): adsim.propensity_model.PropensityModel, which uses only the
    page-context features (the identification assumption). It is scored
    by log-loss, not F1, because DML needs calibrated probabilities. On
    a synthetic pair with a 5% treated arm, F1 was 0.0 for all four
    candidates of the old grid, so the first grid entry won by default.
    Log-loss separated them (-0.194 vs -0.265 for an unrestricted deep
    forest). Leaf candidates target ~10 and ~50 expected rows of the
    smaller arm, min(10 / rare_rate, N/100) and min(50 / rare_rate, N/20).

GROUPING BY USER (--group-col, default global_token_new)
-----------------------------------------------------------
Users contribute many impressions. If one user's rows sit on both sides
of a cross-fitting split, the nuisance predictions for that user are
partly in-sample. When the estimation data has the user-id column, both
the nuisance grid search (StratifiedGroupKFold) and econml's cross-
fitting (groups=...) keep each user's rows together. If an arm has fewer
than 20 distinct users, that rank falls back to row-level folds.
StratifiedGroupKFold can otherwise leave a training fold with no rows of
the arm, which econml rejects. Such arms are far below the click floor
anyway.

Limitation: econml does not pass groups to the final forest, so its
per-tree subsampling and the BLB confidence intervals still treat rows
as independent. Those intervals are likely too narrow. Report user-
clustered bootstrap intervals for any headline statistic.

CACHED TRAINING DATA (--cache-values, off by default)
---------------------------------------------------------
cache_values=True stores the training matrix inside each pickle (about
120 MB for a 400,000-row pair; 154 MB measured). The simulation loads all
~94 forests into every worker process, so caching could cost tens of GB
per process. Nothing in the simulation or analysis notebooks needs it.
Pass --cache-values only for forests you want to call cf.summary() or
refit_final() on.

CLI OVERRIDES
--------------
--arm-ratio-cap (3), --max-samples-cap (200000), --min-clicks-per-arm (5),
--min-var-fraction-leaf (0.1), --n-estimators (500), --group-col
(global_token_new), --cache-values, --random-state (42).

HISTORY: RULES THIS REPLACES
-----------------------------
  - 2024 (produced the submitted paper): max_samples = 0.01 of each pair,
    grid-searched min_samples_split {1000, 2000, 5000} and max_depth
    {10, 20, 30}, n_estimators silently set to 300 by tune(), leaf floor
    left at econml's default of 5 rows, propensity model chosen by F1.
    Small ranks got ~1,000 rows per tree and leaves with ~0 clicks.
  - 7 Sep 2026: fixed min_samples_split 20,000, min_samples_leaf 10,000,
    max_samples 50,000, max_depth 10 for every rank and scenario. It had
    no arm cap, so leaves in the largest pairs held <1 base-ad click. The
    honest halving meant at most one split per tree. The 27 Sep guard on
    max_samples raised for pairs of 50,000-100,000 rows.
  - 12 Sep 2026: leaf floor as a fraction of the per-tree sample
    (H/4, H/2), not tied to clicks, so small pairs could split on leaves
    with almost no clicks. It also used a cv-tuned min_var_fraction_leaf.
